# 0047 — terminal UI

## Context

Runs are watched through `status --watch` and `events --follow`, which are read-only and need a
second terminal for every command. Driving a run from the terminal (approve, answer, abort) has
no single surface. A browser UI would add a server, a port and authentication to a repo-local
tool, and the CLI floor is Node 20.3 while current Ink releases declare Node 22.

## Decision

- Ink **6.4.0** with React **19.3.1**, pinned exactly. Ink 7 and later require Node >= 22, above
  the CLI's `>=20.3` floor; the pin is revisited only with the floor.
- A private `packages/tui` workspace (`@loomwright/tui`) with subpath exports for `entry` and
  dependency-free `strings`. It may import core and protocol but never the CLI; core and
  protocol never depend on it.
- A second lazy bundle: `bun run build` writes `packages/cli/dist/tui.js` beside
  `packages/cli/dist/cli.js`. The `tui` command loads the sibling with a dynamic import built
  from a variable specifier, falling back to `@loomwright/tui/entry` from source. No other
  command imports the entry, so Ink stays out of their startup path.
- Ink's DEV-only `react-devtools-core` peer is stubbed at bundle time: the tool is never
  installed, and the bundle must load on Node 20.3 without it.
- Detached children (opencode servers and long-running gates) run behind a `Launcher`, so
  quitting the UI does not kill a run and reattaching can find it.
- Approval is an overlay driven by the run phase, not a separate screen. Design parks a change
  at `awaiting-approval`; the protocol now carries the additive `approval.pending` event
  (`specHash`, `changeDir`) that the terminal renders.
- `--replay <file>` renders a recorded JSONL event stream through the same tree; `--once`
  renders one frame into an in-memory stdout and exits, so the UI is testable without a TTY.
  `--ascii` forces the glyph set. Without a TTY and without `--replay`, the command points at
  `status --watch` and `events --follow` and exits 1.
- The activity tail is one fold from the run event stream into a bounded 2,000-line ring: every
  event family maps to a line, heartbeats coalesce in place, `.factory/logs/` references are
  named rather than opened, and both layouts show the tail.
- `l` lands a `done` run only: a confirmation, then a detached `land <id>` child through the
  same launcher. The UI never calls `landChange`; the merge happens locally and nothing is
  pushed.

Alternatives rejected: a web UI (server, port, auth); Ink 7/8 (Node 22); a static import of the
TUI from the CLI (every command pays Ink's startup and bundle cost); a separate TUI executable
(a second bin and a second install path to keep in sync).

## Consequences

- `dist/tui.js` is about 1 MB; `ws` (Ink's devtools transport) is the largest avoidable part and
  is the first thing to trim if the size matters.
- Node 20.3 stays the floor: the bundle is proven against `node@20.3.0` and the CI `node-smoke`
  matrix.
- Help, summarised labels and completion metadata stay in `packages/tui/src/strings.ts`, which
  the CLI imports eagerly; the Ink tree stays behind the dynamic import.
- The event stream remains the source of truth for replay, so a recording re-renders the same
  UI without a workspace or an install marker.
- A chatty phase can evict older task lines sooner: the 2,000-line cap is fixed and the tail is
  a live view, not the record.
- In the single-pane layout the tail takes rows from the task graph, so a long tail leaves less
  room for tasks; it is sized to the rows that remain.
- The land child's evidence is its spawn log and the refreshed run list; a failed land shows the
  exit code and log tail and leaves the run and its branches in place.
